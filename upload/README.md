## 命名、版本与便携阅读

- 建议文件名为 `<实验日期>_<实验组或版本>_实验报告.md`；同一想法有多次独立 run 时加入 run 标识，避免覆盖。
- 实验日期与报告整理日期分别记录。采用不同日志时区时明确标注，保留原时间来源。
- 每份报告应自包含关键背景、实际参数、训练/验证结果和判断；链接原文件只作证据补充，不能要求读者先访问服务器才能理解结论。
- 单独复制 Markdown 即可阅读文字、表格和公式；需要亲自查看视频/图片时，另按报告中的准确路径选择媒体，不自动复制大文件。
- 本目录名为 `upload` 不表示已传输到任何外部机器。本次没有自动上传、发送消息或启动后续实验。
- 既有报告的事实更正按日期追加，说明原结论与新证据；新实验另建报告，不能用最新结果抹掉旧实验。

## 每组实验报告应包含的内容

1. 实验名称、run 身份、执行与编写日期、真实完成/失败/未执行状态。
2. 背景与研究问题，和上一轮的关系，方法及对照、主要变化变量。
3. 数据版本、样本身份和来源、训练/验证/测试划分、帧号、相机与分辨率，以及已知适用限制。
4. Base/LoRA 身份、实际权重路径、初始化与加载方式、文本条件、输入预处理、GT 使用边界。
5. 可核对的训练与推理参数、损失定义、采样和随机性控制、真实优化器更新预算、checkpoint 与恢复方式。
6. 实际执行过程：成功阶段、失败退出、中断、恢复、纠正与未完成事项，区分临时检查和正式预算。
7. 环境、耗时和显存及其统计口径；证据缺失时直接注明，不补造数字。
8. 指标公式、聚合口径、训练与验证分开汇总、逐样本差异及对照改善/退步，表中写出关键数值。
9. 实际视觉表现、问题样本和真实帧号、几何/时序/保留区域变化；区分图像检查、视频播放和定量验证。
10. 主要发现、反例、适用范围与未证明事项，最后提出下一步最有信息量的实验建议，明确是否已经执行。
11. 成果清单、运行目录、证据路径和代码入口；读者拿到单份报告也能理解实验，不强制依赖外链。

如果实验失败或只完成一部分，仍可建立注明状态的阶段报告，列清已完成量、未完成量和原因；不能为了“每组一份”把启动脚本或权重存在写成实验完成。
