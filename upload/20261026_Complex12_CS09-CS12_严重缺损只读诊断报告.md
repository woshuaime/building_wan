## 1. 主要判断

**C/U/S 确实是较轻缺损版本 Rev1 上训练出的三份 LoRA，本轮直接用于 OriginalHard，没有针对严重缺损重新训练。CS09、CS11 仍有明显改善；CS10 的连接面恢复错误，CS12 的屋面形状及首尾一致性问题突出。不能把平均 MAE 下降等同于结构恢复成功。**

本次进一步确认了三个容易混淆的事实：

- CS09/10/11 是旧训练建筑上的新缺损位置；CS12 才是这四栋中未参与 C/U/S 训练的建筑。CS10 的失败证明问题不只来自“建筑没有见过”。
- 严重版不是在 Rev1 原缺口上统一扩大面积。CS10、CS12 两版 Exact 在全部 80 个独立视角上的交集为零；CS11 也几乎不重叠。关键连接线索的变化比单一面积数字更有解释力。
- 四栋原始 000/080 的 Damaged、GT、Exact、实际相机位姿，以及适配后的像素条件都相同；**完整内部条件不能据此视为相同**。现有 VACE 的时间压缩使掩码首尾 latent 分别取自原始 001/079，两者不同。该机制和非闭环的时间编码说明相同输入端点不保证相同输出，但其对当前错误的因果贡献仍待验证。

当前最小且有信息量的下一轮，是保持普通 C 的模型、预算和推理设置不变，仅加入轻度/严重缺损混合训练，与旧 C 配对比较。详细方案见第 7 节，**尚未执行**。

## 3. 数据对应与 000/080 实际条件

### 3.1 文件、帧号和相机对应

本次读取两版本 × 四栋 × 四类图像 × 81 帧，共 2592 张输入 PNG（GT、Damaged、Exact、raw_visible），核对尺寸、帧号、二值性与对应关系；没有重渲染数据。

- 每类为连续 000–080，512×512；GT/Damaged 为 RGB，Exact 为二值 0/255。
- 四栋 sample/source 身份与配置、索引一致；相机记录 frame 0–80 与文件编号一致。
- 两版各栋的 81 张 GT、81 张 raw_visible 逐像素相同；相机 `resolutions` 与 `trajectory` 相同。变化发生在 Damaged/Exact 及数据来源/几何校验元数据。
- 两版各栋的 000/080：GT、Damaged、Exact、raw_visible 的 PNG 文件内容及解码像素均相同。
- 每版每栋 000–079 的 Exact 非零像素数均与该版相机文件中渲染检查记录相符，共 640 项匹配。物理相机首尾的内外参、位置相同；差别仅为 frame/frame_id、0°/360° 和 time_seconds 0/5 等记账字段。

因此，**现有证据不支持“错配 GT、掩码整体移位、错一帧或首尾相机不同”是主要故障**。这不是重新证明每个像素的三维可见性：原包仍保留 `complete_automatic_human_pending`/`human_QA=pending`，本次没有做新的几何重渲染验收。

### 3.2 入口相同，不等于整个时序条件相同

实际 [adapt_images](/mnt/windowsE/chuanjun/building_wan/scripts/vace_p01.py:87) 将白区填灰127，白区外逐像素保留 Damaged，不扩大、不羽化。Before 图展示的是原 Damaged，模型在缺口内部实际看到的是填灰后的条件。CPU 调用该适配器与现有预处理后，四栋 000/080 的条件 RGB、ModelMask、归一化 BF16 张量均相同。

但 [WanVideoUnit_VACE](/mnt/windowsE/chuanjun/building_wan/code/DiffSynth-Studio/diffsynth/pipelines/wan_video.py:674) 随后把掩码空间 8×8 重排，再用 `nearest-exact` 将 81 个时间位置压缩到 21 个。按该实现进行 CPU 复现，采样原帧索引为：

`[1,5,9,13,17,21,25,28,32,36,40,44,48,52,55,59,63,67,71,75,79]`

所以首尾 mask latent 分别来自 001 和 079，并不是直接保留的 000/080。形状为 `[1,64,21,64,64]`，每个时间片有 262144 个二值元素：

| 样本 | 首/末 mask latent 不同元素数 | 首/末非零元素并集数 | 首末是否相同 |
| --- | ---: | ---: | --- |
| CS09 | 2231 | 3870 | 否 |
| CS10 | 2143 | 3959 | 否 |
| CS11 | 5209 | 19276 | 否 |
| CS12 | 5990 | 13510 | 否 |

这是按现有代码和真实输入做的 **CPU 数值复现**，不是从旧 GPU 进程捕获的中间张量。未加载模型权重，未执行 VAE 编码，CUDA 未初始化。不同 latent 时间片共同影响整段生成，不能把以上采样点机械解释成每张输出图只对应一张掩码。

另外三项由现有源码支持：

1. [VAE 时间编码](/mnt/windowsE/chuanjun/building_wan/code/DiffSynth-Studio/diffsynth/models/wan_video_vae.py:984) 首先处理单帧000，然后按001–004、005–008……077–080分组并维护因果缓存。首尾视频 latent 所处上下文不同；**本次未计算其具体数值，是否及差多少待验证**。
2. [噪声生成](/mnt/windowsE/chuanjun/building_wan/code/DiffSynth-Studio/diffsynth/diffusion/base_pipeline.py:183) 用一个 seed 生成整段随机张量，没有把首末噪声设为相同。相同 seed 用于方法间复现，不等于时间首尾噪声相同。
3. [时间位置编码](/mnt/windowsE/chuanjun/building_wan/code/DiffSynth-Studio/diffsynth/pipelines/wan_video.py:1620) 区分时间位置。推理无 GT 参考帧、无端点锁定、无相机闭环约束，也不将预测080替换成000。

**诊断结论：原始数据首尾对应正确，模型没有强制闭环。** 掩码时间映射、VAE 上下文、噪声与时间位置是可能影响首尾差异的机制；目前没有受控消融，不能宣称其中某一项已经被证明是 CS12 的唯一根因，也不能据此把原实现直接认定为数据 bug。这些机制同样存在于旧 Rev1 和五种方法中，不能单独解释 C/U/S 与 L 的差异。本轮保持实现原样。

已有评审为每栋九张连续帧联系图、覆盖 000–080，另有六张原尺寸重点图；本次重看重点图、两版数据对照图并独立核算端点。完整连续帧观察同时参考 [既有逐段复核记录](/mnt/windowsE/chuanjun/building_wan/outputs/vace/complex12_originalhard_eval/run_20261026_012033/review/notes.md)，视频解码与对齐采用既有 [媒体检查记录](/mnt/windowsE/chuanjun/building_wan/outputs/vace/complex12_originalhard_eval/run_20261026_012033/checks/delivery_media.json)。

当前可以确认 CS12 首尾同视角形状不一致，以及若干中间视角的连接恢复不正确；**没有光流补偿、三维对应或实时播放产生的闪烁定量结果**。不能将不同相机的相邻帧 RGB 差直接当成闪烁，也不能把静态图复核写成已经证明了全圈三维一致性。

## 7. 建议的下一轮最小实验：普通 C 的轻/重混合训练

本节为建议，未创建新实验目录、配置、权重或运行任务。目的只检验：**在相同预算下改变缺损覆盖，能否改善严重连接恢复，同时保住轻度版本效果。**

### 7.1 对照与唯一主要变化

| 项目 | 旧 C 对照 | 新 C_mix 建议 |

| 初始化 | 旧共同初始化 + 原始VACE | 使用同一份共同初始化 + 原始VACE |
| 训练数据 | Rev1训练8栋 | 相同8栋；仅CS09/10/11混合Rev1与OriginalHard |

**不要从旧 C step300 再续训300步后称为同预算对比。** 建议使用既有 [shared_initialization.safetensors](/mnt/windowsE/chuanjun/building_wan/outputs/ComplexSingleOrbit_Rev1_Pilot_20261022/checkpoints/shared_initialization.safetensors)，新 AdamW 状态起步，以免把数据版本变化与额外训练预算混在一起。

这一轮保持现有 VACE 骨干、Mask预处理/时间映射、文本与81帧采样不变。前文发现的内部时间条件差异先作为记录，暂不与混合数据试验同时改动，否则无法判断收益来源。

### 7.2 保持8/4划分，避免复制数据改变建筑权重

训练仍为 CS01/03/05/06/07/09/10/11；验证仍为 CS02/04/08/12。**CS12 的两种缺损都不得进入训练**，不能因为它失败就把该建筑加入本轮训练。

只训练 **一组 C_mix，300 次真实优化器更新**。旧 C 在两版上的结果已存在，直接复用；不重跑 B/L/U/S，也不搜索多个seed或超参数。

### 7.4 怎样判断这一轮有没有价值

新 C_mix 与旧 C 在**同一数据版本、同一原始帧号**上比较，再分别看：

1. **严重版训练身份三栋**：缺损MAE/MSE/PSNR、结构Sobel、known、全图/缺损区闭环；逐栋报告，不让CS09/11的好结果掩盖CS10连接错误。
2. **严重版未训练CS12**：单独报告全部指标，并固定复查B000/B080的异常折面是否消失。即使均值下降，错误连接或首尾形状不一致仍应判为未解决。
3. **Rev1训练8栋、验证4栋**：分别列新C减旧C的绝对差、相对差、逐栋退步数量和退步最明显的样本；轻度性能下降必须单列，不能用严重版收益抵消后宣称总体成功。
4. **原样控制建筑**：CS01–08中训练身份5栋、验证身份3栋单独查看，有助于判断数据分配改变是否干扰原能力。
5. **固定结构反例与完整轨迹**：CS09 B006；CS10 B024/B058；CS11 B073；CS12 B000/B080，加上每栋000–080全序列。比较缺口是否封闭、屋脊是否接到正确位置、坡面/墙面交线是否保持，以及原有完好轮廓是否移动。不要按新模型最漂亮的帧另选展示。
6. **判断边界**：同一seed的配对小试用于方向筛选，不产生多seed统计显著性。CS12已经被用于本次诊断，下一轮即使改善，也仍是沿用验证集的开发证据，不能包装成全新未触碰测试集。

如果严重版连接恢复改善、轻度没有明确退步，支持继续扩大**缺损形态覆盖**，保持骨干不变；若只改善训练身份建筑而CS12仍失败，说明迁移覆盖尚不足；若严重版收益伴随轻度退步，要先记录和理解数据分配的取舍。若相同预算的混合训练仍无法改善连接和闭环，再考虑把几何/Depth或时序约束作为下一项独立研究变量，不能预设它们已经必要或有效。
