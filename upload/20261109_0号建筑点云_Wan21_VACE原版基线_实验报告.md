## 1. 结论先行：实验跑通，点云补全效果尚未达标

本次确实完成了 **1次原版VACE局部视频补全推理**：81帧、832×480、16 FPS、30个扩散采样步骤，父进程记录GPU worker正常退出，返回码0。没有训练模型，没有加载LoRA，没有追加第二次正式推理，也没有将普通文生视频结果当成带mask补全。

生成区域出现了大量小点状亮纹，但整体更像**黑色底上的密集规则点阵或网格面**，没有达到“点与点之间露出浅灰背景、颜色和间距接近周围观测点”的目标。结果没有简单恢复成输入那样的纯灰色平面，但仍有明显的整片墙面感，不能写成已经成功生成自然、稀疏的点云墙面。

环绕过程中的建筑大轮廓基本保持；生成墙面的规则纹理随视角变化，首尾重复视角的结果明显不一致。原有观测点也有重绘，不能保证逐点或逐像素保留。

| 最初要回答的问题 | 本次证据支持的回答 | 结论范围 |

## 9. 实际视觉表现，按帧段具体说明

本轮报告阶段重新完整解码81张原始PNG和两条81帧视频；静态观察覆盖全部000–080帧的建筑区域联系图，并检查000、020、032、047、060、080的原像素局部对比，以及044–046、058–060相邻帧。局部固定裁剪范围为原图x=200–639、y=90–419，仅用于查看，不曾送入模型。

复核材料保存在原run新增目录：

```text
report_review_20261109_024727/
```

其中六张`all_frames_*.png`覆盖全部81帧，`crop_pair_*.png`是输入/预测局部对照，`adjacent_*.png`是相邻帧对照。静态图生成及查看均为CPU工作，没有重跑模型。

### 9.1 000–002：窄侧墙被填成密集暗色点纹

000帧输入左侧灰墙被生成成黑底上的密集亮点，轮廓大致沿mask区域。邻近原观测点是大小较清楚、颜色偏灰绿、间隔较大的单点；生成点则小而密、对比强、规则性高，形成明显风格断层。001–002墙面随视角收窄，密集纹理仍在，不是自然稀疏点的延续。

### 9.2 003–029：没有白区也发生了原观测点重建

这27帧mask全黑。预测大体保留屋顶与建筑边缘的布局，但020局部输入/预测对比可以看到：原本较清楚的圆点边缘变得不规则，一些点连成小块，屋顶细节和间隙发生变化，背景有轻微重建差异。

这说明本入口的黑区保留是条件约束，不能理解为输出直接复制原始观测像素。它同时提供了观察重建改动的案例，无需把这些帧当成新的补全任务。

### 9.3 030–043：侧墙展开后出现规则网格与行列结构

030帧白区仅735像素，右侧墙刚出现；032帧白区增至5702，窄墙呈密集蓝黑/亮色条纹。之后大墙面展开，040帧可见覆盖整个生成立面的规则点阵，并有较明显纵向行列结构。

此时不是完全没有小点，而是生成纹理整体太密、太整齐，暗底填满点间空隙，未保持提示词要求的浅灰背景通透感。周边屋顶和边缘仍保持大体位置，但已知区点形状不完全相同。

### 9.4 044–050：正面大墙的点阵规律最强

044–046相邻帧和白区最大的047帧尤其清楚：生成立面呈一整块近黑色平面，上面重复排列细小亮点/短线，局部有黄白色高亮竖列。原观测点较大且分散，两者密度、明度、颜色与排列规律都不匹配。

建筑大轮廓没有突然跳到另一种物体，但小点纹理的表面感很强。仅凭这些帧不能将“不是光滑纯色墙”解释为“已经符合点云”。

### 9.5 051–063：双立面生成，转角及纹理变化明显

随相机继续绕行，第二面墙逐渐出现。两个相邻立面的暗色规则纹理、尺度与方向并不完全一致，转角和檐口附近有较宽的浅色分隔带。058–060连续图中可以看到局部行列和亮纹分布变化。

这些是时序不稳定的静态线索。由于相机本来就在运动，本次没有相机配准、逐点对应或实时播放，不能把每一个纹理变化都断言为同一三维点发生漂移，也没有量化高频闪烁。

### 9.6 064–080：大轮廓延续，闭环外观不一致

大墙面仍以密集条列/网格形式存在，随后逐渐转成窄侧面。080与000的输入及mask完全相同，但生成纹理、明暗和周边细节不相同。首尾结果没有硬性复制，因此保留了这个真实的闭环问题。

本次最明确的时序结论是“重复输入视角没有得到一致的生成外观”，不是已经测得了点云三维漂移，也不是已经证明每个中间帧都闪烁。

## 10. 报告阶段的CPU辅助数值核查

本轮没有完整GT或可靠的三维点ID，故不报告缺口恢复MAE、三维Chamfer、真实点数恢复率等指标。为了核实已知区改动与首尾问题，仅补充以下像素检查，结果存于`report_review_20261109_024727/cpu_review.json`。

比较使用原始预测PNG与解码后的输入RGB，避免把MP4二次压缩当成模型误差。令原始预测为P、输入为I、白色mask为M，已知区平均绝对差定义为：

```text
MAE_known = sum(|P - I| over all RGB channels and all pixels where M=0)
            / (3 × number of pixels where M=0)
```

跨81帧汇总时对已知区像素加权，RGB值范围0–255。它衡量原样保留程度，不衡量模型补全是否正确；背景像素占比很大，因此均值较小也不能证明观测点完全保真。

| 辅助检查 | 结果 | 解释 |
| --- | ---: | --- |
| 全81帧已知区MAE，0–255 | 2.409225 | 原始生成的黑区并非输入的逐像素副本 |
| 同值归一化至0–1 | 0.009448 | 上行除以255 |
| 27个全黑mask帧的全图平均MAE，0–255 | 2.334306 | 即使没有指定生成白区，也存在重建改动 |
| 000/080输入RGB是否完全相同 | 是 | 提供同视角首尾比较条件 |
| 000/080输入mask是否完全相同 | 是 | 白区可用同一像素集合比较 |
| 000/080原始预测全图MAE，0–255 | 3.897315 | 全图首尾存在差异 |
| 000/080原始预测白区MAE，0–255 | 75.957650 | 生成区首尾差异突出；归一化约0.297873 |
| 000/080原始预测黑区MAE，0–255 | 2.598990 | 已知区首尾也非完全一致 |

逐帧已知区MAE示例：000为1.906576，020为2.451745，040为2.848716，047为1.931235，060为2.463428，080为2.726489。不能用047均值较低证明其点云补全较好，因为该指标只比较白区外，且受大面积浅色背景影响。

没有用相邻帧直接相减构造“闪烁分数”，原因是相机运动会引入正常像素变化；也没有把黑区所有像素微小差异的比例叫成“观测点被破坏比例”。
