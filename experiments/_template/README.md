# 新实验说明模板

状态：模板，未运行。复制到experiments/vace/<idea>/或experiments/t2v/<idea>/后填写；模板本身不创建run或启动GPU。

## 研究问题与对照

说明想解决的具体问题、对照实验和唯一或主要变化变量。写出可以观察的成功/失败条件，不预设新方法胜出。明确本实验与历史Base、LoRA或Composite的关系。

## 数据身份与划分

填写数据版本、绝对数据根、样本编号到源建筑的映射、训练/验证/测试身份、原始帧范围及重复闭环帧处理。说明全黑Mask语义、抽窗规则、尺寸与相机对应；注明验证数据和GT不得进入哪些条件。

## 方法与固定配置

记录模型来源、LoRA分支/目标层、rank/alpha、初始化、精度、优化器、学习率、batch/累积、真实更新预算、随机种子、保存点和恢复能力。推理另记录帧数、尺寸、FPS、步数、CFG、正负文本、Mask适配和后处理。

写明哪些配置与对照逐字相同、哪些改变。配对实验记录共享初始化、采样/噪声序列及各方法独立优化器。不存在或不兼容的方法应标未执行，不填假结果。

## 文件组织

```text
experiments/<task>/<idea>/
├── README.md
├── scripts/
├── configs/
└── runs/<run_id> -> 原始输出目录

outputs/<task>/<idea>/<run_id>/
├── 00_看结果/
├── checkpoints/
├── predictions/
├── metrics/
├── logs/
├── resolved_config.json
└── progress.json
```

只创建实际需要的目录。专用源码在experiments，公共组件从scripts/code复用。原始数据和历史大结果不因归类而移动；新run不覆盖旧配置、权重和完成标记。

## 执行预算与恢复规则

填写训练次数、每组更新数、推理轨迹总数、执行顺序、必要中间检查和停止条件。区分safetensors增量与完整optimizer/RNG恢复状态；说明哪些成功项可复用以及匹配条件。记录用户实际授权范围，准备脚本完成不代表运行已获授权或实验已完成。

## 指标、可视化和证据

列明误差参考对象、区域、数值范围、逐帧/逐栋/跨栋汇总、空Mask处理、闭环帧与常规帧关系。说明同步面板、关键帧如何选择以及预测是否原始；不能按预测最好看的帧挑选证据。

运行后填写真实输出数、退出码、实际optimizer更新、可解码媒体、耗时和显存口径。失败尝试与成功结果分别记录，保留未运行/失败原因。

## 结果与后续

分别回答训练与验证表现、主要改善、退步、残留几何/时序问题和证据局限。下一步建议单列，不自动启动。更新根目录四份状态文档及实验台账，按项目规则完成检查和Git记录。
